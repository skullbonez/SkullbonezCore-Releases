# SkullbonezCore 2026.09.27.1

This update fixes saving: a **SAVE** button now sits in the top bar and **Ctrl+S** saves from anywhere. It also makes large block builds much faster, especially in Edit mode and on laptops, and restores edge smoothing that the 2026.09.27 download could not load.

## Download and run

Extract the entire Windows ZIP to a writable folder. Run **Launch SkullbonezCore.cmd**, or run **SKULLBONEZ_CORE.exe** from that folder. Keep **SkullbonezData**, **ThirdPtySource** and the DLLs beside it. You need 64-bit Windows and a DirectX 12-compatible GPU and driver; no development tools are needed. This portable build is unsigned.

The included **SkullbonezCore-First-Time-User-Manual.pdf** explains the controls. Open **Tutorial** in the top bar for guided practice. Optional Solver Lab comparison recordings are omitted from the portable ZIP.

## Save your level

1. Look at the top bar, right of the **Edit mode / Playback** button. A red **SAVE** means your level has unsaved changes; a grey **SAVED** means everything is saved.
2. Click **SAVE**, or press **Ctrl+S** in Edit mode or Playback. The **Save scene** button in **Editor Controls** does the same thing.
3. A message near the top of the view confirms **Saved <level>**, or explains why saving failed.
4. The demo that opens at startup and the tutorial practice levels have no level file of their own. Saving them creates a copy, such as **Demo_copy** or **tutorial_build_copy**, opens it as your level and leaves the original unchanged. Later saves update the copy.
5. Saved levels reopen with everything you placed. Loading a level restarts its undo history and replay timeline.

## Faster editing with large builds

Scenes with hundreds or thousands of blocks now run much faster, especially in Edit mode:

- Blocks hidden behind other blocks are no longer fully shaded, so walls, towers and piles cost far less GPU time. Spheres and planets look and behave as before.
- While you place a large wall, pyramid or other block structure (more than 128 blocks), the preview shows one outline around the whole structure instead of an outline for every block. Smaller structures still preview each block.

- On laptops with both integrated and dedicated graphics, the game now asks Windows for the faster GPU instead of taking the default one.
- The download no longer turns on DirectX's developer checks when Windows Graphics Tools happen to be installed. Those checks slow every frame.

On our test PC, a 2,048-block wall in Edit mode went from about 6.3 ms to about 2.0 ms of work per frame, and the blocks' GPU time from 3.6 ms to 1.0 ms. Your results depend on your hardware. If a large build is still slow, try **Options > Video > Min**.

## Edge smoothing and frame rate

The 2026.09.27 download was missing one shader file used for edge smoothing (SMAA). The game kept trying to load it every frame, which cost frame rate on every machine and left edges jagged. This download includes it, the release packager now refuses to build a download with any missing shader file, and the game no longer retries a shader that failed to load every frame.

## Look and cinematic fixes

- The default look now uses the higher-contrast ACES colour grade. The flat **Neutral colour** curve is off by default; your saved graphics settings drop it once when you upgrade, and you can turn it back on in **Options > Video**.
- Beach balls in the cinematic modes use their mode's own lighting again.

## Notes and feedback

**SAVE** (or **Ctrl+S**), **Replay > Save recording** and **Camera > Save path** write different things. **F2** makes a separate scene shot; it does not save the active level.

Ray-traced reflection is experimental. Frame rate depends on the scene, selected effects and hardware. Solver Lab's optional comparison recordings are not included in this download.

Please include this version, the scene, your steps and what happened in the [public issue tracker](https://github.com/skullbonez/SkullbonezCore-Releases/issues).
