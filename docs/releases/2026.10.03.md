# SkullbonezCore 2026.10.03 - Slow motion, physics and replay fixes

This update adds per-viewpoint Director slow motion, an optional Box3D solver, better debris settling and adaptive CPU scheduling. It also fixes disappearing fallen bodies, pyramid replay restoration and several editor history and scene-saving problems.

## Download and run

Extract the entire Windows x64 ZIP into a writable folder. Run **Launch SkullbonezCore.cmd** or **SKULLBONEZ_CORE.exe**. Keep **SkullbonezData**, **ThirdPtySource** and the DLLs beside it. Requires 64-bit Windows and a compatible DirectX 12 GPU and driver. This build is unsigned.

Open **Tutorial** in the header for guided practice. The included **SkullbonezCore-First-Time-User-Manual.pdf** covers the fundamentals; these notes describe the newest controls. The [2026.10.02 notes](https://github.com/skullbonez/SkullbonezCore-Releases/releases/tag/v2026.10.02) describe the retained water, search, Properties and panel changes.

## Sweep the camera through slow motion

1. Enter **EDITING** and open **Camera**. Move to a view, choose **Capture view**, then move and capture another. A path needs at least two viewpoints.
2. Set **Timing: Independent**. Scene-speed keys are disabled with Scene time because that mode follows the replay clock.
3. Expand **Properties > Director viewpoint**. Use the camera picker arrows to select a captured viewpoint. Adjust **Scene speed**: 1x is normal, values below 1x are slow motion, and 0x freezes the scene while the camera keeps moving. The slider applies when released.
4. Choose **Speed easing** to cycle Linear, Ease in, Ease out or Ease in-out. This controls the transition from the selected viewpoint's scene speed to the next viewpoint's speed. Set a later viewpoint back to 1x to return to normal motion.
5. Choose **Play path** to preview. **Pause path** stops path playback; **Restart path** returns the path to its beginning. The Camera pane's **Scene slower** and **Scene faster** buttons also adjust the selected viewpoint. **Faster/Slower** adjust the camera path duration separately.
6. Use **Save path** to retain the viewpoints, speed keys, easing and timing in the scene's separate `.shot.json` file. **Load path** replaces the current path with that saved copy. Saving the scene alone is not a substitute for Save path.

Normal camera navigation remains right-mouse look with **W/A/S/D**, **Q/E** down/up, **Shift** boost, and wheel speed adjustment while looking. Release right mouse before editor shortcuts. Director cameras following scene time now track the interpolated bodies more closely, reducing visible camera/body jitter.

## Fallen bodies and replay

Falling beyond the terrain's lower boundary or leaving the supported world now freezes bodies at a safe position instead of deleting them. Their identities remain available for selection and recorded playback. Black-hole capture remains a separate behavior.

Try **cine_pyramid_rainbow.scene.json**: play the scene, pause, scrub earlier recorded time and resume or restore from that point. Restoring sleeping pyramid islands now preserves their recorded state instead of failing with a solver-hash mismatch. **Restart**, **Reset**, and entering Edit restore the authored starting arrangement. Save authored changes with **SAVE** or **Ctrl+S** to keep them after reopening.

Saved replay restoration, snapshots and prediction now account for the sleep-plane state. Sun-death sequence overrides are cleared when changing scenes, so the next scene does not inherit the collapsing star's appearance or replay policy.

## Settling piles and choosing Box3D

1. Return to the live scene, leaving loaded recordings, historical replay and comparisons before changing Physics settings.
2. In **Physics > Simulation**, **Pile stabilization** is an optional, default-off setting that helps almost-still debris piles settle together. Changing it starts a new recording. Save the level to retain it.
3. For newly placed physical objects, **Start sleeping** keeps them still until contact disturbs them. Enable it before placement; it is distinct from making an object static. Save the scene to preserve authored objects.
4. The solver chooser now includes **Box3D**, a graph-coloured soft-step solver. Select it and choose **Apply & restart** to restart with it; **Revert** abandons an unapplied selection. **Show colours**, available while Box3D runs, draws contact groups so you can inspect the work distribution. Turn it off to return to the ordinary view.
5. Use **Save Physics defaults** to retain an applied solver choice for later launches. The live **SOLVER LAB** remains available for comparisons. Different solvers can produce different results; Box3D is optional, not a replacement for the default.

## Performance and presentation

Worker scheduling now adapts to measured job cost and available CPU threads. Small jobs can stay on the calling thread, while larger work is divided among workers. Hull contacts, broadphase discovery and debris solving have further improvements. Actual frame rate depends on hardware and scene load; larger worker pools can use a few additional megabytes of memory.

The gravity grid's cost is bounded independently of body count. The **solar_system_sun_death.scene.json** showcase has a softer, more open gravity well and spiralling forecast presentation. Distant grass is more even, with grass blades sharing the turf's shadowing. Launcher laser/reticle and manipulator tether presentation are steadier. **G** toggles the broadphase overlay without changing camera tracking.

## Editor and reliability fixes

- Hull scale, copy, paste and Undo retain usable asset recipes; saving preserves authored hull paths and editor tokens.
- Pasted joints stay within the copied assembly. Changing scenes clears old clipboard recipes. Undo/Redo can traverse history even when earlier targets have disappeared, and selection drops dead members.
- Combo boxes activate within their visible fields. Editor **K** no longer also steps the Director.
- Collision-volume overlays follow the displayed pose, including compound objects and transparent presentation.
- Replay compaction and consecutive frame reads preserve body data. Prediction roots and long supported horizons have correctness fixes.
- Idle frames avoid repeated scene-browser path copies, reducing allocation churn. Scene requests can complete while the application is unfocused.

## Saved files and feedback

Back up personal scenes before saving them with a new version. Editable scenes, recordings, camera paths and Solver Lab sessions are separate saves. New personal levels and demo/tutorial copies go in **Documents/SkullbonezCore/Levels**. Older recordings may not be compatible with changed formats; retain the earlier application if needed. Optional stabilization changes physics behavior; use the settings appropriate for your scene.

Solver Lab's optional comparison recordings are not included in this download.
