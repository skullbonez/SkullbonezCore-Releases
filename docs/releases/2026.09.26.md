# SkullbonezCore 2026.09.26

This release adds easier editing and playback controls, grouped copy/paste, remembered minimum-spec options, and new domino and arch blocks. It also includes cached UI rendering and sustained frame-cost improvements.

## Download and run

Extract the entire Windows ZIP to a writable folder. Run **Launch SkullbonezCore.cmd**, or run **SKULLBONEZ_CORE.exe** from that folder. Keep **SkullbonezData** and the DLLs beside it. You need 64-bit Windows and a DirectX 12-compatible GPU and driver; no development tools are needed. This portable build is unsigned.

The included **SkullbonezCore-First-Time-User-Manual.pdf** explains the controls. Open **Tutorial** in the top bar for guided practice. Optional Solver Lab comparison recordings are omitted from the portable ZIP; use separately supplied comparisons to explore Solver Lab.

## Switch between editing and playback

1. Click the top-bar mode button: **Edit** has a red background and **Playback** has a green background. The existing **Edit scene** buttons still mirror this state.
2. You can enter Edit mode while inspecting a later simulation time. The objects and scrubber return to the authored starting arrangement.
3. If you change nothing, click **Playback** to return to the retained playback position and future.
4. The first actual edit immediately discards that future. Undoing the edit does not restore the discarded playback. Press **Play** to run again from the start; Play also leaves Edit mode for you.

The bottom scrubber is grey and ignores dragging when there is no recorded or predicted interval to inspect. **Play** remains available and creates a new future, enabling the scrubber as time becomes available.

## Select, copy and paste a group

1. Enter Edit mode and choose **Select [Q]**. Click an object or drag a selection rectangle; **Ctrl-click** toggles objects in the selection and Ctrl adds to a rectangle selection.
2. Press **Ctrl+C**, then **Ctrl+V**, or use **Copy [Ctrl+C]** and **Paste [Ctrl+V]** in Editor Controls.
3. The copied standalone objects appear together with their relative arrangement, sizes and appearance retained. The pasted group is selected and slightly offset so it can be moved into place.
4. Use **W** to move, **E** to rotate or **R** to scale. **Ctrl+Z** undoes the paste as a group; **Ctrl+Y** or **Ctrl+Shift+Z** redoes it. Use **Save scene** to keep the result.

This clipboard supports standalone editable objects; it is not a general copier for every linked or jointed assembly. Q/W/E/R tool shortcuts now work while the pointer is over editor panels. Release right mouse first, and finish typing in text fields or close popups before using shortcuts.

## Rescue a build by making its blocks static

1. Load your existing level through **Tools > Scene** and enter Edit mode.
2. Select the blocks that should stay fixed, including a multiple selection.
3. In **Editor > Controls**, click **Make static**. The selected blocks retain their identity, authored positions and appearance instead of falling when the simulation starts.
4. Use **Make physical** to let them move again. Conversion clears motion; use **Ctrl+Z** to undo if needed.
5. Click **Save scene** before closing or changing levels. Conversion and the saved result work with older saved block levels too.

The unavailable tester level was represented during testing by a reconstructed older-format fixture based on the supplied image; the missing original file itself could not be tested.

## Two independent minimum-spec options

Open **Options** and use **Min-spec graphics** and **Min-spec physics** independently or together. Both choices are remembered after restarting the app.

- **Min-spec graphics** disables anti-aliasing and costly effects, including shadows, reflections, clouds, god rays, volumetric lighting and bloom. Turn it off to restore the underlying graphics choices.
- **Min-spec physics** reduces the solver iteration budget without changing the simulation timestep. Turn it off to restore the configured budget. Fewer iterations can make complicated stacks and constraints less stable; making scenery static can be a better choice for a large fixed build.

The switches reduce work in their respective systems. The resulting frame rate depends on the scene and hardware.

## Dominoes and a red arch

In **Editor > Objects**, choose **Domino** or **Red arch**, then click and release over the terrain to place it. The wheel raises the preview; Ctrl-wheel turns it. Choose **Select [Q]** when finished placing.

**Domino** uses the same narrow proportions as the supplied **catto_double_domino.scene.json** scene: 1 thick, 4 high and 2 wide. Its face has round dots and a divider; the stretched marking has been corrected. Save and reopen a scene to retain the markings and dimensions.

**Red arch** has a flat top and an open, faceted archway underneath. It starts as a static building piece. Its collision uses only six pieces, with a clear doorway and solid sides and crown. It supports placement, copying, undo and scene saving.

## A smaller tutorial on smaller screens

Click the tutorial title-bar **minus** button to collapse it to a small bar, freeing the viewport. Click **plus** to expand it and continue from the same tutorial progress. **Tutorial** in the top bar remains the entry point.

## Existing controls to keep handy

- Hold **right mouse** and move the mouse to look; use **W/A/S/D** while held to fly. Release it to operate the editor. Middle-drag pans and the idle wheel zooms.
- In **Minecraft mode**, left-click places, right-click removes and **Esc** releases the mouse. **1 / 2 / 3** select Move / Rotate / Scale; **4** turns 90 degrees; **5** snaps to ground; **6** resets. Wheel zooms, Ctrl-wheel turns and Shift-wheel adjusts height.
- **Save scene** saves the editable level. **Replay > Save recording** saves a separate recording. **F2** creates a scene shot and does not save the active level.
- In Edit mode, **Camera** beside Replay supports a director path: move the view, release right mouse, **Capture view** at two or more positions, then **Play path**. **Space** pauses/resumes; **Save path / Load path** use a separate `.shot.json` file.
